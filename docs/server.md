# Развёртывание и первый сеанс

На Linux-сервере нужны Docker Engine с Compose v2, около 2 ГБ свободной памяти и диск с записью от 10 МБ/с. Управление наблюдениями выполняется из браузера. На одном томе запускайте один экземпляр приложения. База оборудования — RTL-SDR Blog V3. В образе установлен пакет Debian rtl-sdr с утилитами rtl_sdr и rtl_eeprom.

## Первый запуск без SDR

```sh
git clone https://github.com/samsonovAleksandr/radio-telescope.git
cd radio-telescope
cp .env.example .env
docker compose up -d --build
```

На сервере откройте **http://127.0.0.1:8080/**. Для доступа из домашней сети в .env задайте LISTEN_IP равным LAN-адресу интерфейса сервера, например 192.168.1.20. Выполните `docker compose up -d` и откройте с другого устройства **http://192.168.1.20:8080/**. Адрес примера замените своим. Этот режим предназначен для доверенной локальной сети. Сервис разрешает управлять приёмом любому клиенту, имеющему доступ к порту.

1. Выберите «Водород Млечного Пути», источник «Встроенная демонстрация», участок ON, задайте имя «Диск» и нажмите «Получить запись». Две секунды демонстрации занимают 9,6 МБ.
2. Повторите с участком OFF и именем «Фон». Выберите «Диск» как основную запись, «Фон» как опорную. Ожидается широкое превышение порядка 60% около 1420,406 МГц. В полном диапазоне видны разрывы на центре и краях. Наведите курсор или вращайте колесо над графиком. Сохраните CSV, PNG и метаданные.
3. Введите 1420,40175–1420,40975 МГц и нажмите «Подготовить звук». Включите по очереди проигрыватели основной и опорной записи. Сохраните WAV. Переключите преобразование, снова подготовьте звук. Уровень регулируется общим ползунком перед подготовкой.
4. Выберите «Импорт файла IQ», укажите файл CU8 (I,Q,I,Q; байты 0…255), центр и частоту дискретизации. Внесите известные усиление, ppm, модель приёмника, конфигурацию усилителя и сведения о наведении. Метка времени создания в JSON обозначает время поступления в архив. Для старого файла внесите исходное время UTC в поле заметок. Один байт в конце без парного Q считается ошибкой. Хвост короче кадра FFT не входит в накопление. При неизвестном усилении оставьте поле пустым. Отдельный спектр доступен, сравнение требует одинаковых известных настроек.
5. Для тренировочного «живого» источника задайте SIMULATE_SDR=1 и выполните `docker compose up -d`. Выберите USB и накопление 30 с. Нажмите «Остановить» во время записи. В архиве останутся только законченные записи. Верните SIMULATE_SDR=0 перед работой с приёмником.

При повторном импорте IQ можно выбрать сохранённый JSON проекта рядом с файлом CU8. Интерфейс заполнит параметры и признак модельного сигнала. Для искусственного тестового файла без JSON выберите «Модельный сигнал» вручную. У импортированных измерений статус «Эксперимент». Статус «Подтверждено наблюдателем» присваивает оператор после полевых проверок, связывая измерение с повторной записью при другом центре и своим протоколом.

## USB на физическом Linux-хосте

1. Подключите только нужный V3. Найдите его строку командой `lsusb` (пример Bus 001 Device 004), определите путь /dev/bus/usb/001/004. Убедитесь, что этот узел соответствует серийному номеру вашего SDR. Остановите программы, которые держат устройство. При конфликте DVB-T освободите интерфейс тюнера на хосте. Перед отключением драйвера убедитесь, что им не пользуется телевизионный приёмник.
2. Назначьте этому устройству групповое чтение и запись через udev. Пример правила /etc/udev/rules.d/70-radio-observer.rules для типовых VID/PID и существующей группы plugdev приведён ниже. Подставьте VID/PID из lsusb и серийный номер своего устройства. Его можно увидеть в `udevadm info --attribute-walk --name=/dev/bus/usb/001/004`.

   ```udev
   SUBSYSTEM=="usb", ENV{DEVTYPE}=="usb_device", ATTR{idVendor}=="0bda", ATTR{idProduct}=="2838", ATTR{serial}=="ВАШ_СЕРИЙНЫЙ_НОМЕР", GROUP="plugdev", MODE="0660"
   ```

3. После `sudo udevadm control --reload-rules` переподключите приёмник, снова проверьте номер устройства. В .env задайте SDR_DEVICE с текущим полным путём и SDR_GID с числом из `stat -c %g /dev/bus/usb/001/004`. Запустите:

   ```sh
   docker compose -f compose.yaml -f compose.usb.yaml up -d
   ```

   Контейнер получает один USB-узел с rw и числовой GID владельца группы. Процесс работает под UID 10001, корневая ФС доступна для чтения, capabilities сброшены. После переподключения путь может измениться — обновите .env и пересоздайте сервис. [Справочник devices и group_add](https://docs.docker.com/reference/compose-file/services/)

4. В браузере выберите «Приём через USB» → «Проверить SDR». Сначала запишите 5 с при входе с нагрузкой. При 2,4 Мвыб/с получите 24 000 000 байт. Сверьте усиление в метаданных, отсутствие обрывов и долю предельных кодов АЦП, затем переходите к проверке земля/небо. В режиме живого захвата команда rtl_sdr работает с фиксированным усилением и поправкой, без ключа -T. Для данного тракта требуется выключенный bias tee; проверьте его состояние вольтметром у отдельно подключённого SDR до присоединения МШУ. [Руководство Blog V3](https://www.rtl-sdr.com/rtl-sdr-blog-v-3-dongles-user-guide/)

## Хранилище и расчёт

Именованный том observations содержит для каждого UUID raw.iq, meta.json и spectrum.json, а также общий settings.json. Это обычные файлы, пригодные для резервного копирования. Временный каталог записи становится каталогом наблюдения после окончания обработки. При прерывании сеанса он удаляется. При аварийном завершении незаконченные временные каталоги очищаются при запуске. Обычные `docker compose down` и `up` сохраняют том при том же имени проекта. Ключ down -v удаляет том. Для переноса архива остановите сервис, скопируйте том штатным средством резервного копирования Docker и восстановите с владельцем 10001:10001.

MAX_UPLOAD_MIB ограничивает отдельную загрузку, MAX_CAPTURE_SECONDS — один захват, RESERVE_MIB — свободное место после записи. Значения по умолчанию 2048 МиБ, 300 с, 128 МиБ. На экране показано свободное место тома. При 2,4 Мвыб/с час CU8 занимает 17,28 ГБ. Для часа одним файлом увеличьте лимит соответствующей операции и проверьте запас диска. Новая запись занимает диск до ручного архивирования. Для большей серии рассчитайте место заранее.

FFT использует неперекрывающиеся кадры по 2048 комплексных отсчётов, окно Ханна и среднее **линейной** мощности. Двусторонняя PSD нормирована на Fs × сумму квадратов окна и полный масштаб каждой компоненты 127,5 кода. Шаг при 2,4 Мвыб/с — 1171,875 Гц, эквивалентная шумовая полоса окна около 1759 Гц. Значения дБFS/Гц требуют калибровки для перевода в дБм/Гц или кельвины. Отбрасываются края |f−fc| ≥ 0,42 Fs и центр ±10 кГц. ON/OFF вычисляется как 100 × (P_ON/P_OFF − 1). Профиль, сетка, тракт, приёмник, усиление и ppm должны совпадать. Для двух разных центров сравнивайте результаты **двух отдельно рассчитанных пар** по абсолютной радиочастоте.

В солнечном профиле график и CSV содержат интеграл PSD по рабочей полосе во времени. Каждая точка усредняет последовательные кадры. График использует общую шкалу для ON и OFF. Для исключения измеренных узких помех и усреднения до фиксированного временного шага при дополнительном анализе используйте сохранённые IQ. Новый профиль добавляется в web/profiles.json: уникальный id, имя, объект, frequency и band в Гц, центр, Fs, секунды, способ калибровки, аппаратные требования, view (spectrum или time), audio (noise или spectrum). Затем пересоберите контейнер. Встроенный сигнал моделирует два включённых профиля. Для нового научного метода нужна соответствующая модель и проверка.

## Внешний доступ

Оставьте LISTEN_IP=127.0.0.1, установите Caddy на тот же хост, настройте DNS имени сервера и доступность TCP 80/443. Получите хеш через `caddy hash-password` (ввод пароля по приглашению). Подставьте домен и хеш в Caddyfile, проверьте конфигурацию `caddy validate --config /etc/caddy/Caddyfile` и перезагрузите Caddy. Пример для Caddy ≥2.8:

```caddyfile
radio.example.org {
    basic_auth {
        observer ВСТАВЬТЕ_ХЕШ
    }
    reverse_proxy 127.0.0.1:8080
}
```

Откройте свой HTTPS-адрес. Без учётных данных сервер должен вернуть 401 и после входа показать панель. Входной порт 8080 остаётся на loopback. Реальные DNS, сертификат, пароль и доступ снаружи проверяет владелец при развёртывании. [Авторизация Caddy](https://caddyserver.com/docs/caddyfile/directives/basic_auth)
